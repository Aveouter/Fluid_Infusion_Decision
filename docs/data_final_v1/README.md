# Final提取数据包 v1

这是后续补液研究统一使用的提取后数据契约，依据2026-10-19用户确认的患者范围、内容范围和不确定性策略建立。发布状态与文件指纹以本地包manifest和公开RELEASE.json为准；不能用文件夹名字代替核验状态。

## 内容与患者范围

- 原始来源449人全部进入来源与资格索引；缺少基线入院时间的33人明确排除，不推算入院时间。
- 主数据416人，保留333名历史开发患者和83名历史留出患者的分组元数据；所有人使用相同数据规则，不在数据发布过程中训练模型或计算模型成绩。
- 观察范围为伤后前72小时。每人保留72个小时网格，完整住院小时、部分边界和观察外小时分别标记。
- 包含静态基线、结构化体征、原文检验/生理数值、尿量原记录、晶体/胶体/水三类静脉液体、单列口服/鼻饲液体、设备设置曲线、批次账、分段输入量、证据与因果历史状态。
- 原始CSV、医生原表和基线原表不被覆盖。患者原文、身份键、逐记录信息、明细数据包均仅本地保留；公开PR只含方法、字典、提取工具、合成测试及汇总核验。

## 数据入口

```text
Final包/
├── manifest.json              # 状态、版本、来源、生成代码及文件指纹
├── cohort/patients.csv        # 449人资格与时间边界
├── baseline/values.csv        # 416人基线长表及来源行
├── observations/              # 逐观测账与小时汇总；不插补
├── fluid_events/              # 医生、护理、加液、辅助用途及回顾处置
├── fluid_lots/                # 瓶/批次原量、取消、消耗和剩余
├── fluid_segments/            # 设备设置与推断输入分段，分表保存
├── hourly/                    # 三类静脉量/速度与单列口服液体
├── causal_history/            # 起点前来源条件下的剩余区间/估计
├── evidence/                  # 完成量约束、冲突、时钟和监督资格
├── provenance/                # 来源行、纠错/推断账、生成输入和冻结recipe
├── dictionary/                # 逐表逐字段及临床变量字典
└── validation/                # 独立算术/来源核验
```

CSV采用UTF-8（含BOM），空单元格表示未知或不适用。主数据不做训练集插补、标准化、归一化或固定长度窗口；实验可以在其训练患者内部拟合预处理，不修改Final包。

可选数组适配器`python -m tools.final_data.adapter --package 包路径 --out 新适配目录`分别生成predictors.npz和targets.npz，保留NA且不拟合预处理。预测读取器不读取小时标签、完成账或不确定性标记；sample提供起点前已完成临床bin、每个历史bin结束时已知的补液状态历史、起点当前状态及已可用基线。药物泵记录与单位未定的尿收集量有独立角色标记，不能直接宣称都是已验证的生理变量。

targets另提供已量化原始主补液加液量recorded_source_added_ml及独立资格，用于需要新增量辅助任务的实验；它是按事件小时归属的登记量，不称完整真实加液量，含未知量线索或手术区间来源不明的小时不给该任务精确资格。

## 三种容易混淆的量

|字段|业务含义|
|---|---|
|整瓶/整次来源量|进入待输库存的液体总量，不是该小时已输入量|
|设备设置速度|医生表与明确护理原句的文书设置；保存小时起点、结束前值及设置时长积分|
|小时实际输入量参考|从有限库存、分段速度及完成/处置约束重建；有些片段含估计，方法逐条保留|

完整一小时的平均输入速度=input_ml/1h，与设备设置速度分列。设置时长积分也不等于实际输入量；库存耗尽、小时内变速、估计分配及未记录的过程均可能导致差异。

## 后续实验读取规则

1. 小时[h,h+1)的量标签用input_ml；设备末点标签用end_setting_ml_h。起点设置和设置积分是不同字段。预测窗口默认仍为未来1小时，多小时目标由后续协议从同一小时表汇总。
2. 量、设置、精确联合监督分别使用quantity_reference_eligible、setting_reference_eligible、exact_joint_eligible，不能只保留对某模型有利的小时。完整原参考值及排除原因同时保留。
3. 不能把整份提取表、事后完成量、net_ml、质量标记或回顾性小时量直接作为在线特征。主因果状态只读取起点前已发生且已可见的来源；临床小时观测只消费已结束的bin。
4. 对状态同时使用remaining_lower_ml、remaining_upper_ml和明确标注的中点估计。未知初始设置不是0；已登记容量只是来源条件账，不是经泵遥测验证的真实容量。
5. 历史留出患者已经在既有研究中使用，不能将其称为新取得的外部验证。保留原分组只用于追溯；新的评估设计须独立登记。
6. 冻结后数据文件不原地修改。纠错建立新版本，记录字段、数值、掩码、患者/小时分母和来源规则的差异，并同步更新所有公平对照。

## 核验含义

源指纹、原表一致性、分段积分、库存核算、因果时点和文件完整性检查属于程序与来源核验。独立医生盲法复核仍未完成；“Final”表示本次研究数据规则和版本固定，不表示每条记录已取得独立临床真值认证。

详细提取方法见[METHODS.md](METHODS.md)，逐表字段见[fields.csv](fields.csv)，临床变量与聚合规则见[clinical_fields.csv](clinical_fields.csv)。原始来源、当前提取、回顾性估计与预测输入的边界在方法中分别说明。
